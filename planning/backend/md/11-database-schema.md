# Backend — Database Schema (PostgreSQL 16)

The physical schema for the whole system, written as **PostgreSQL DDL**. It is ORM-agnostic and is the source of truth for migrations. If Prisma is confirmed (T-02), the Prisma schema is derived from this file (see [§25](#25-prisma-mapping-notes)).

It implements the entities in [03-domain-model.md](03-domain-model.md), the lifecycles in [04-state-machines.md](04-state-machines.md) and the rules in the module docs. Schema areas that depend on open decisions are marked **(D-xx)** in comments.

## 1. Conventions

| Topic | Rule |
|---|---|
| Schemas | One PostgreSQL schema per module area (`identity`, `org`, `svc`, `fin`…). A module writes only to its own schema. Cross-schema foreign keys are kept for integrity |
| Primary keys | `id uuid` generated by the **application as UUIDv7** (time-ordered, index-friendly). Reference tables use stable text codes as keys (e.g. `vehicle_types.code`) |
| Human references | `reference text UNIQUE` with a format `CHECK` (`LX-260148`, `PO-260083`…). Values come from `sys.reference_counters` in the same transaction |
| Timestamps | `timestamptz` everywhere (stored UTC). Every mutable table has `created_at` and `updated_at` (set by the trigger in [§22](#22-triggers-append-only-tables-and-invariants)). Business dates without time (`cargo_ready_date`) are `date` in Riyadh local |
| Money | `core.halalas` (bigint ≥ 0, 1 SAR = 100 halalas). Signed amounts (adjustments) use `core.signed_halalas`. Currency is `SAR` only. No `numeric`/`float` for money |
| Rates | `core.bps` basis points (1500 = 15%, 350 = 3.5%) |
| Quantities | `numeric(12,2)` for weights, volumes, pallets and units. `integer` for marketplace units |
| Geo | `geography(Point, 4326)` (PostGIS) |
| Enums | Native PostgreSQL enums in the `core` schema. Values are only added (`ALTER TYPE … ADD VALUE`), never renamed or removed |
| Polymorphic links | **Exclusive arcs** (nullable FK per target + `CHECK (num_nonnulls(...) = 1)`) where there are ≤ 4 targets. Generic `*_type` + `*_id` columns (no FK) for documents, cases, conversations, audit |
| Soft delete | `deleted_at` only on user-managed catalog data (addresses, products, vehicles, sites, bank accounts). Never on financial or lifecycle rows |
| Concurrency | `version integer NOT NULL DEFAULT 1` on aggregates edited concurrently (orders, quotes, products, stock, settlements) |
| Arrays of file ids | `uuid[]` for evidence photo lists (no FK possible; the application validates ownership and scan status) |
| Naming | snake_case, plural tables, `ix_` indexes, `ux_` unique indexes, `ck_` checks, `fk_` deferred foreign keys |
| Drafts | Detail tables allow NULLs so multi-step drafts can be saved. Completeness is validated by the application at submit |

## 3. Shared domains and functions

```sql
CREATE DOMAIN core.halalas        AS bigint  CHECK (VALUE >= 0);
CREATE DOMAIN core.signed_halalas AS bigint;
CREATE DOMAIN core.bps            AS integer CHECK (VALUE BETWEEN 0 AND 10000);
CREATE DOMAIN core.currency_code  AS char(3) DEFAULT 'SAR' CHECK (VALUE = 'SAR');

-- Keeps updated_at current (attached to every table with updated_at in §22)
CREATE OR REPLACE FUNCTION core.set_updated_at() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END $$;

-- Blocks UPDATE/DELETE on append-only tables (in addition to REVOKE)
CREATE OR REPLACE FUNCTION core.forbid_mutation() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION '% on %.% is not allowed (append-only table)', TG_OP, TG_TABLE_SCHEMA, TG_TABLE_NAME;
END $$;

-- Arabic search normalization: strips diacritics and tatweel, unifies alef/yaa/taa marbuta,
-- converts Arabic-Indic and Persian digits to Western digits, lower-cases Latin text.
CREATE OR REPLACE FUNCTION core.normalize_ar(input text) RETURNS text
LANGUAGE sql IMMUTABLE PARALLEL SAFE AS $$
  SELECT lower(
    translate(
      regexp_replace(coalesce(input, ''), '[ً-ْٰـ]', '', 'g'),
      'أإآٱىة٠١٢٣٤٥٦٧٨٩۰۱۲۳۴۵۶۷۸۹',
      'اااايه01234567890123456789'
    )
  )
$$;
```

## 22. Triggers, append-only tables and invariants

```sql
-- 1) updated_at on every table that has the column
DO $$
DECLARE r record;
BEGIN
  FOR r IN
    SELECT c.table_schema, c.table_name
      FROM information_schema.columns c
      JOIN information_schema.tables t
        ON t.table_schema = c.table_schema AND t.table_name = c.table_name AND t.table_type = 'BASE TABLE'
     WHERE c.column_name = 'updated_at'
       AND c.table_schema IN ('identity', 'ref', 'org', 'files', 'svc', 'freight', 'transport', 'warehouse',
                              'customs', 'mkt', 'fin', 'ops', 'msg', 'sys', 'cms')
  LOOP
    EXECUTE format('CREATE TRIGGER trg_set_updated_at BEFORE UPDATE ON %I.%I
                    FOR EACH ROW EXECUTE FUNCTION core.set_updated_at()', r.table_schema, r.table_name);
  END LOOP;
END $$;

-- 2) Append-only tables: triggers + REVOKE (§24)
DO $$
DECLARE t text;
BEGIN
  FOREACH t IN ARRAY ARRAY[
    'org.consents', 'files.document_versions', 'files.document_reviews', 'svc.order_events', 'svc.quote_revisions',
    'transport.trip_events', 'warehouse.stock_movements', 'fin.ledger_transactions', 'fin.ledger_entries',
    'fin.invoice_lines', 'ops.case_internal_notes', 'audit.audit_logs']
  LOOP
    EXECUTE format('CREATE TRIGGER trg_append_only BEFORE UPDATE OR DELETE ON %s
                    FOR EACH ROW EXECUTE FUNCTION core.forbid_mutation()', t);
  END LOOP;
END $$;

-- 3) Double-entry invariant: debits = credits per ledger transaction, checked at commit
CREATE OR REPLACE FUNCTION fin.assert_transaction_balanced() RETURNS trigger
LANGUAGE plpgsql AS $$
DECLARE
  v_debits  bigint;
  v_credits bigint;
BEGIN
  SELECT coalesce(sum(amount) FILTER (WHERE direction = 'DEBIT'), 0),
         coalesce(sum(amount) FILTER (WHERE direction = 'CREDIT'), 0)
    INTO v_debits, v_credits
    FROM fin.ledger_entries
   WHERE transaction_id = NEW.transaction_id;
  IF v_debits = 0 OR v_debits <> v_credits THEN
    RAISE EXCEPTION 'Ledger transaction % is unbalanced (debits %, credits %)', NEW.transaction_id, v_debits, v_credits;
  END IF;
  RETURN NULL;
END $$;

CREATE CONSTRAINT TRIGGER trg_ledger_balanced
  AFTER INSERT ON fin.ledger_entries
  DEFERRABLE INITIALLY DEFERRED
  FOR EACH ROW EXECUTE FUNCTION fin.assert_transaction_balanced();

-- 4) Issued invoices are immutable (only ZATCA fields and file links may change); no deletes
CREATE OR REPLACE FUNCTION fin.protect_invoice() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  IF (NEW.number, NEW.invoice_type, NEW.issuer_org_id, NEW.recipient_org_id, NEW.recipient_name,
      NEW.issue_at, NEW.subtotal, NEW.vat_amount, NEW.total)
     IS DISTINCT FROM
     (OLD.number, OLD.invoice_type, OLD.issuer_org_id, OLD.recipient_org_id, OLD.recipient_name,
      OLD.issue_at, OLD.subtotal, OLD.vat_amount, OLD.total) THEN
    RAISE EXCEPTION 'Issued invoice % is immutable; issue a credit note instead', OLD.number;
  END IF;
  RETURN NEW;
END $$;
CREATE TRIGGER trg_invoices_immutable BEFORE UPDATE ON fin.invoices FOR EACH ROW EXECUTE FUNCTION fin.protect_invoice();
CREATE TRIGGER trg_invoices_no_delete BEFORE DELETE ON fin.invoices FOR EACH ROW EXECUTE FUNCTION core.forbid_mutation();

-- 5) Marketplace search vector (category and supplier names are appended by the search indexing job)
ALTER TABLE mkt.products ADD CONSTRAINT ck_products_specs_array CHECK (jsonb_typeof(specs) = 'array');

CREATE OR REPLACE FUNCTION mkt.products_search_vector() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  NEW.search_vector :=
       setweight(to_tsvector('simple', core.normalize_ar(NEW.name)), 'A')
    || setweight(to_tsvector('simple', core.normalize_ar(coalesce(
         (SELECT string_agg(e->>'value', ' ') FROM jsonb_array_elements(NEW.specs) AS e), ''))), 'B')
    || setweight(to_tsvector('simple', core.normalize_ar(coalesce(NEW.description, ''))), 'C');
  RETURN NEW;
END $$;
CREATE TRIGGER trg_products_search
  BEFORE INSERT OR UPDATE OF name, description, specs ON mkt.products
  FOR EACH ROW EXECUTE FUNCTION mkt.products_search_vector();
```

### Invariants: where each one is enforced

| Invariant | Database | Application |
|---|---|---|
| Money totals add up (quotes, orders, POs, checkout, invoices, settlements, charges) | `CHECK` constraints | Computes the values |
| Ledger balanced per transaction | Deferred constraint trigger | Builds postings |
| One live quote per provider/request, one live payment intent per payable, one open cancellation per order, one live broker authorization per order | Partial unique indexes | Friendly `409` errors |
| Stock never negative | `CHECK` on `inventory_items` | Row lock + movement insert in one transaction; nightly Σ check |
| Marketplace reservations ≤ stock | `CHECK` on `products` | Reservation TTL job |
| Commission rules don't overlap in time | `EXCLUDE` constraint | Maker-checker flow |
| Maker ≠ checker | `CHECK` on batches, approvals, rules, refunds, cancellations | Hides approve button |
| State transitions (request, quote, order, payment, settlement, document, KYB, return, case, …) | Enum values only | Transition tables ([04-state-machines.md](04-state-machines.md)) |
| Tenant isolation (org scoping) | FKs only | Every query scoped by the membership org (RLS optional later) |
| Refunds ≤ amount paid | `refunded_amount <= amount` | Sums refunds before creating one |
| One active trip per driver / vehicle | — | Row lock on driver and vehicle at assignment |
| Evidence file ownership and scan status | — | Validated on attach (arrays have no FK) |
| Append-only history | Triggers + `REVOKE` | Correction rows instead of updates |

## 25. Prisma mapping notes

Applies if T-02 confirms Prisma.

| Topic | Approach |
|---|---|
| Multiple schemas | `datasource db { schemas = ["core", "identity", "ref", ...] }` with the `multiSchema` feature (a preview flag on older Prisma versions); every model and enum gets `@@schema("...")` |
| Naming | Models in PascalCase with `@@map("service_requests")`; fields in camelCase with `@map("snake_case")` |
| IDs | `String @id @db.Uuid`, generated in the app with a UUIDv7 library. Don't use `@default(uuid())`, which generates v4 |
| Money | `BigInt` in Prisma → JS `bigint`. Convert at the API boundary with a Prisma client extension. SAR amounts in halalas stay below 2^53, so `Number()` is safe |
| Domains | Prisma sees the base type (`bigint`, `integer`). The domain `CHECK`s live in SQL migrations |
| PostGIS | `Unsupported("geography(Point, 4326)")`; read and write with `$queryRaw` / TypedSQL |
| `citext`, `inet`, `cidr[]` | `@db.Citext`, `@db.Inet`; `cidr[]` as `Unsupported` |
| Not expressible in the Prisma schema | Partial unique indexes, expression/GIN indexes, `CHECK` and `EXCLUDE` constraints, generated columns, triggers, partitioned tables, views, grants. Write them in SQL migrations (`prisma migrate dev --create-only`, then edit) and check `prisma migrate diff` in CI so they are never dropped silently |
| Partitioned tables | Queried like normal tables. Partitions are created by migrations / pg_partman |
| Enum arrays | Supported (`CustomsMovement[]`) |
| Alternative | If Drizzle is chosen instead, `pgSchema`, enums, partial indexes and checks are expressible in TypeScript, so less raw SQL is needed. This is part of the T-02 tradeoff |
